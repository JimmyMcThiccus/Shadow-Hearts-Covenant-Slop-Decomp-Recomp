## 2. Program architecture (from JP symbols + decompilation)

```
main()                                 (app.cpp)
 ├─ FullAllocAndFree, mwInit, CApp::InitialReset, SetRebootPath, InitScreen(512x448)
 ├─ app = new CApp(prio 1, 0xF, stack 0x10000)   ← a CThread subclass
 ├─ app->StartThread(); SleepThread()            ← main thread sleeps forever
 └─ CApp::Run()  (thread body, infinite loop):
      World::BeginUpdate / WorldRender / EndUpdate   (OT / VIF1 packet rendering)
      CPoller(0x60).Polling()      ← system poller: SSHSys lives here
      if !paused: CPoller(0x48), CPoller(0x54)   ← game pollers (scene objects)
      m_pAppFunc()                 ← optional hook
      ScreenBright::Draw, sceGsSyncPath, DelayDeleteObject flush, screen capture
      Gsx::DrawSync, VSync / force flip, UpdatePolBreakState, DoReset check
```

`CApp::InitInstance` → `InitMain` → `SSHMain` (IOP reboot, load IRX modules, FileIOLib, Sdrv, `new SSHSys`, `SSHSys::Initialize`: CPad, Overlay cache, RegDatApi, JRing, BgEffectMan, LoadFieldData, Sdrv reverb/sound buffer, LSDPlayer, BtlSaveSec, InitFieldSaveData, MenuObj, CVibeMan) then `opening()` → `SSHSys::SetAPI(new CDMYStage)`.

**`SSHSys`** is the scene manager. It owns one current `SSHApi` (virtual: `Start`, `Polling`, `preLoad`, `closeInquiry`, `Pause`, `Reset`) plus a pending one; `Polling` runs a 2-phase handover (closeInquiry old → Start new). `PollingApi` handles transition requests via a byte at +0x36:
- `0x10` → `InitFieldSocketM` (field scene, loads FIELD.BIN through `Overlay::Load`)
- `0x20/0x21` → `StartBattle` → `InitBtlSocket` + `BtlSocket::SetPC/SetMonsterSet` (BATTLE.BIN)
- `0x30` → `GameOver`

`SSHApi` implementations: `CDMYStage` (title/opening), `CFieldSocket` (field; drives `CField` in FIELD.BIN, world map, shop, solomon, Cmd* menus), `BtlSocket` (battle; drives `CBattle` in BATTLE.BIN), `GameOver`.

Core engine services (all in main): `Gsx`/`GsxCamera`/`GsxFrameBuf` (GS setup, flip), `World` (ordering tables of `VIF1Prim` packets), `Model`/`ExModel`/`Atomic`/`Frame`/`SkinAtomicPack2`/`BlendShape` (skinned models + motion), `LightControl`/`ShadowControl`, `Texture`/`ClutRaster`, `EffectCore`/`Effect*`/`Fp*`/`Puti*`/`JRing` (particle & judgement-ring effects), `CScript`/`CScriptEx` (event script VM: byte-coded RPN machine, engine hooks via `CScriptEx` ids 0xC0 = LSDScrEx, 0xC2 = CField), `VEC` (effect VM executing `.EFD`/`HECO` programs from EFFECT.PKB; its ~270 system calls are the `xxxName__FiiPPcPv` handlers in `FuncTbl`), `LSDPlayer` (cutscenes), `MovieServerHandler` (MPEG via libipu), `Sdrv`/`SdrvEE`/`HNMSnd`/`CSe`/`CMusic`/`StreamBGM` (audio), `FileIOLib`/`DvdromOrder`/`BufMemory`/`RegDatApi` (I/O + PKB), `Menu*` (menu widget toolkit), `SaveData`/`SaveDevice*` (MC/HDD saves), `CPad`/`CVibe`, `CThread`/`CPoller`/`CPolObj`/`CPause`/`CTimer`.

## 5. Conventions

- Ghidra programs: `SLPM_602.19` (JP main, symbols), `SH2JP_FIELD.BIN`, `SH2JP_BATTLE.BIN`, `SLUS_210.41` (US, stripped). Always pass `program=` explicitly.
- Keep JP mangled names as the canonical key (e.g. `Polling__6SSHSysFv`). Demangle in notes as `SSHSys::Polling()`.
- Struct names in Ghidra: the class name verbatim (`SSHSys`), fields `m_name` where the symbol table gives them.
- Rust: one module per C++ class or source file; `// JP: 0x003b6230 Polling__6SSHSysFv` comment on every ported fn.
- After any large feature is added or edited, take sanity screenshots (`sh2_app --us --autoplay --boost 80 --shots <dir>`) and look at the *other* screens too (field, battle menu / ring / result, in-game menu); compare with `notes/integration/screens/win_us/`.  Sprite layer ids in `sh2_menu::bevy_ui::layer` are one shared namespace (8 menu, 9 field screens + battle HUD, 10 world map, 11 radar): grep before adding one.
- Never commit disc data into `port/`; the Bevy app reads the original disc folder via `SH2_DISC_DIR`.
