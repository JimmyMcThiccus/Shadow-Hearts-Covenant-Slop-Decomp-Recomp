# Effect data file format (EFFECT.PKB)

`EFFECT.PKB` (106 MB, JP demo; US retail same layout) is a plain concatenation of **261** effect files, each
starting on a 0x800 (CD sector) boundary with the magic `EFMG` (found by scanning: first at 0x0, 0x2d000, 0x64000, ...).
Individual effects are addressed by *name* — `EffectCore`/`CField::StartEffect` build the path `"EFFECT/%s"`
(string at 0x3ff078 / 0x558fe0) and read it through `DvdromOrder::ReadOrder` → `FileIOLib` (the PKFINFO.TBL name
index and the name→offset hashing belong to section A).  Everything below was verified by parsing all 261 files with
`port/crates/sh2_gfx/src/effects/efmg.rs` + a Python disassembler (all opcodes known, all syscall ids in the table).

## 1. `EFMG` container

```
0x00  "EFMG"
0x04  u16 count           (8..10 in practice)
0x06  u16 version = 1
0x08  8 bytes unused (garbage / zero)
0x10  count x { u8 kind, u8 index, u16 0, u32 offset }      offsets relative to the file start
...   padding with 0x40 ('@') up to the first section (0x80 aligned)
```
Sections are stored in directory order; a section ends where the next begins (the loader never needs a size:
every sub-format is self-describing).  `EffectCore::Create` (0x00300ee0) only acts on `C` and `T` at load time;
`M A E L 1 P Y S O` are looked up on demand by VSM system calls (`GetDataPtr`/`CreateWorkModel`/...).

| kind | magic | meaning | count over all 261 files |
|---|---|---|---|
| `C` | `HECO` | VSM bytecode program (exactly one per effect) | 261 |
| `M` | `SSH1` (`SSH1.01a`) | model (standard game model format, section C) — `mdlCreate(n)` creates `M[n]` | 825 |
| `A` | `SQHD` (`SQHD003_00`) | motion. Index bit 7 = standalone motion usable with `CreateMotion`; plain index n is the motion that belongs to model n | 1045 |
| `E` | `EFCM` (`EFCM0002`) | camera motion (§3) — `camCreate(n)` | 715 |
| `L` | `EFLT` (`EFLT0001`) | light motion (§4) — `lgtCreate(n)` | 238 |
| `1` | `SDRH` | Sdrv sound bank: `LoadSe` → `Sdrv::AutoLoad` | 104 |
| `P` | `BBPF` (`BBPF0001`, inner `BBPL`) | "custom" line model for `BBPLineModel` (`cusCreate`) | 23 |
| `Y` | `HTFH`(`HTDT`) | hit data for `HitCylinder`/`HitShot` (`hitCreate*`): header `"HTFH0001"`, u16 key-table offset*0x10 at +8 | 89 |
| `S` | `HTFH` | same format, used for shadow volume (`mdlCreateShadow`) | 18 |
| `O` | `VIBE` or `TIHD` | vibration pattern (`vibCreate`, `VIBE`) or texture header (`pphCreateTexture`, `TIHD`) | 29 + 11 |
| `T` | `TXPS` / `TXTX` | texture pack consumed by `vpTextureFile` (only 4 effects: the rest use game-wide textures) | 4 |

Index byte: for `GetDataPtr(kind, value, mask, mask2)` (0x00303e40): exact match when `mask==0xffffffff`, otherwise
`(index & mask) != 0 && value == (index & mask2)` (used for the "bit 7 = standalone" and shadow lookups).

## 2. `HECO` — VSM program

```
0x00 "HECO"   0x04 u32 version = 3 (anything else is rejected)
0x08 u32 off_SGCN   0x0c u32 off_SGCD   0x10 u32 entry_pc
SGCN: "SGCN" u32 size (<= 40000) 8 zero bytes, then `size` bytes = initial data segment (globals, strings, constants)
SGCD: "SGCD" u32 ninsn  8 zero bytes, then ninsn x 8-byte instructions {u8 op, u8 rel, u16 0, i32 operand}
```
`EffectCore::CreateVec` (0x00301050) allocates a `VEC` (0x254 bytes, each with its own 40000-byte data memory
and the *shared* instruction array), copies SGCN to offset 0, points the instruction segment at SGCD+0x10 and
sets the entry pc.  Programs are 2.9k..6.9k instructions; the first ~2.9k are an identical **prelude** of
wrapper functions (one per system call: `subbp; st32 args; push &arg; setarg i; sys id; jmp epilogue`) generated by
the effect compiler ("VSM", a C-like language — locals addressed `[bp+k]`, calling convention: callee stores its
arguments from the stack with `st32 k[bp]`); the effect's own code follows and the start stub is always
`setbp 40000; call main; end` at `entry_pc` (the last three instructions).  In the 261 files the most used system
calls are `shrGetWorldPos`, then the prelude-only ones that every effect calls once (`blr*`, `btl*`, `sys*`).

Opcodes (all 63 decoded; 0, 17, 52-54 never occur in data): see `vsm.rs` header and `notes/D/effect_system.md` §4.
Stack discipline: assignment expressions leave their value on the stack (`st32.s` family keeps the value and
pops the address); statement-expressions are followed by `pop`.  Execution proceeds without limit until the
program yields: `sysWaitSystem` (id 200) yields one frame, `mdlWaitMotion` blocks until the model's motion
end callback fires, `sysWaitCreateEffect` until the async load of a nested effect finishes,
`waitthr id` until all threads with that id are gone.

### System calls
269 entries, ids grouped by hundreds (`vec*` 0-4, `mat*` 100-110, `sys*` 200-211, `cal*` 250-259, `pgr*` 300-309, `pol*`
400-408, `mdl*` 900-928, `cus*` 1000, `btl*` 1100-1133, `cam*` 1200-1215, `hit*` 1300-1315, `chr*` 1400-1408, `col*` 1500,
`spr*` 1600, `shr*` 1700-1711, `qua*` 1800, `lgt*` 1900, `sse*` 2000, `blr*` 2100-2112, `pph*` 2200-2208, `fld*` 2300,
`gny*` 2400, `bng*` 2500, `str*` 2600, `pth*` 2700, `bfd*` 2800, `lsd*` 2900, `fef*` 3000-3007, `pad*` 3100, `vib*` 3200,
`sbg*` 3300, `xxxCall` 32000).  Full table (also `port/.../syscalls.rs`, `notes/D/vec_functbl.txt`) at the end of this file.
Each handler has the signature `int fn(int id, int argc, char **args, void *ctx)`; `args[i]` are pointers into the
thread's data segment, outputs are written through them.  The handlers live in `EffectFunc*.cpp`-style code between
0x00305c00 and 0x0032f000 and mostly forward to `EffectCore::Create*` / `EffectModel`/... (section E owns the
generic script handlers; these are the *effect-VM* variants).

## 3. `EFCM` camera motion
```
"EFCM" "0002"  u16 @8 = table_offset/0x10   ('ROOT' name record(s) follow, 0x10 each)
table: "EFCT"? u16 count @+4, keys at +0x10, each 0x40 bytes:
  f32[4] eye @0x00   f32[4] target @0x10   f32 time @0x20   u16 fov @0x24   f32 roll @0x2c
```
`EffectCameraMotion::GetData` (0x0030a420): keys searched linearly; exact time → that key; between two keys → linear
blend of eye, target, fov (as float truncated to u16) and roll; time ≥ last key (or before the first!) → last key and
"ended" flag.  Ported as `motion.rs::CameraMotion` (unit tested).  `EffectCamera` adds `LookAt` (builds the GsxCamera
view matrix from eye/target/roll/fov), vibration (`SetVibratePower`, `GetVibPower`), box cameras (`GetBoxPos`) and
"vector" cameras (two FVectors).

## 4. `EFLT` light motion
```
"EFLT" "0001"  byte @8 bits0-2 = light type (0 point, 1 directional, 2 spot, 3 ambient)  u16 @0xc = table_offset/0x10
table keys 0x40 bytes: f32[4] colour @0, f32[4] pos @0x10 (replaced by origin when sampled), f32[4] dir @0x20, f32 time @0x30
```
`EffectLight::LightOn(b)` creates the `LightControl` light (Point/Directional/Spot/Ambient) at `attachFrame.worldPos + offset`;
`ChangeLight` pushes the sampled colour/pos/dir each frame.

## 5. Other static data in the executable
* `FuncTbl` 0x003f89b0 (269 x 12 bytes {id, fn, kind}) — hashed (mod 0x83) into `funcHash` at start-up (`InitSysFunc`).
* `_BI_Pol_Data` 0x003fa8e0 (0xf8c bytes) — read only by `BtlIn::CreatePolygon` (battle intro, section H): a table of 16-byte polygon records after a `0x01007000` header word (`{u32 0, u16 3 (vertex count), u16 0x87, u16 i0, u16 i1, u16 0xffff, u16 0x8000, ...}` with consecutive vertex-slot indices starting at 0x7d).
* `noiseData` 0x00402c10 (0x1090 bytes) — read only by `CGhostEfx::MakePacket` (ghost/spirit distortion): header words `0x0040 0x0040 / 0x0001 0x0001 / 0x0020 0x0020`, then 4-byte entries `v v v 0x80` (grey noise with GS alpha 0x80).
* String literals: `"HECO"` 0x3ff030, `"SGCN"`, `"SGCD"` (the section magics), `"EFFECT/%s"` 0x3ff078, `"Effect Script: zero divede PC=%d\n"` 0x3fee50.
