## Coverage

* Static (call sites found by the recursive-descent scan, `script_survey`): JP 43 scripts - 94 distinct field ops, 5 782 call sites; US 546 scripts - 123 distinct ops, 134 347 call sites. Every id of both sets is handled by `FieldHost` (checked by `--example ops_coverage`: the only ids that reach the "not implemented" arm are ids the original `CallFunc` does not handle either: 0x13, 0x3e, 0x3f, 0x47, >= 0x8d). Implemented: all 123 (JP table 0x00-0x7f minus the unused ids + vector math 0x80-0x8c + the six retail-only ops 0x1b/0x2b/0x2f/0x4c/0x4d/0x77 + retail 0x06). Remaining: none by id.
* Retail-only `SetFieldData` selectors (0x24-0x38) are stored, not acted on (`RetailState::field_data_ex`).
* Dynamic: `cargo run --release -p sh2_field --example script_corpus [-- --us]` runs the start function and every event (args 1, 2, 4) of every map through the real `FieldHost` with a rebuilt runtime per event, answering waits with circle presses and servicing no scene changes:
  * JP: 43 maps, 636 321 engine calls, **0 calls to unimplemented ops**, 280 scene-change requests (map jump / battle / world map / menu, recorded and the VM rebuilt), 5 jobs still running at the budget (start function 3000 ticks, events 6000): `SM_07_U` start + event 1 (x3) and `SM_15_U` start - long `GetTimer` waits.
  * US (start functions only, `--max-events 0`): 543 of 546 maps build (`AR_15_DB`, `FI_01_DB`, `SU_21_U` have no MPS), 176.9 M engine calls, **0 unimplemented ops**, 55 scene-change requests, 34 start functions still running after 3000 ticks (50 s): 20 are `GetTimer` polling loops (`MI_xx`), the rest slow auto-moves / path moves (walk speed is the real 0.30 units per tick) or patrol loops. With 60 000 ticks 4 of 6 sampled ones finish (`HE_07_U`, `GT_10_U`, `SM_33_U`, `SA_00_U`); `YO_02_U` (path-move loop) and `MI_03_U` (timer) keep waiting.
* Unit tests: `host::tests` (vector math, `SetFieldData` event boxes / encounter rate, `WaitModel` follows the motion command, `DoWarp` waits for the effect, inventory through the save block), `script_actors::tests`, `script_ui::tests`, `sh2_script::disasm::tests`.

## Findings that changed existing behaviour

* Event arguments: `CField::SetFieldEvent`/`CallFieldEvent` call the script event with `[trigger]` for event boxes: **enter = 1, leave = 2, examine = 4** (the first port passed 2 for enter and 1 for leave) and `[a2, model slot]` for model events. Box triggers are gated like `CField::Polling`: enter needs `mask & !flags & 1`, leave `mask & flags & 2`, examine `mask & flags & 4`, where `flags` = low nibble of the box flag byte and `mask` = bits 2-4 of `CField+0x18c` (5 after `InitSDB`, op 0x23 sel 0 sets it); op 0x23 sel 1 / 2 / 3 rewrite those bits (`FieldSim::evt_mask`).
* Faders: `SetFader(slot, mode, ms)`: the third argument is **milliseconds**, mode 0 = fade *from* the colour to clear (starts opaque), 1 = to opaque, bit 1 = white, modes 6/7 = half-strength; slot 1 (op 0x28) is in front, slot 0 (op 0x29) behind the windows. Ported with `socket::Fader` (the exact `UpdateFader`).
* Facing: `GetRotAngle(i)` has 32 directions (`i * pi / 16`), the original model forward is -z (`rot.y = atan2(-dx, -dz)`), so the simulation's direction-of-travel yaw is `rot + pi` (`script_actors::rot_to_yaw`). `ENTRYPOS.dir` was previously read as 1/256 turn.
* Op 0x70 is `SetWorldMapPoint(index, state)` (writes the `WM` chunk), not a getter; 0x71 is `WorldMapJump`; 0x28/0x29 are the screen faders (the provisional names "SoundObj1/0" were wrong); 0x66 `InventoryChange`, 0x6f `DiskChange`, 0x7d `ParamChange`, 0x7e `SavePoint`.
* Scripted battles: ops 0x72 / 0x73 (`InvokeBattleTbl` reads the `BBTL` chunk of `FIELD/FIELD_T.DAT`) start the battle through the same `BattleFlash` -> `SSHSys::StartBattle` path as random encounters; AP_02_U's central ring now triggers the scripted tutorial battle (`InvokeBattleTbl 0`).
* Player speed: walk / run 0.30 / 0.83 units per tick (root translation of the walk / run motions).
